# Telegram для Claude (telegram-mcp)

Локальный MCP-сервер, который даёт Claude доступ к вашим Telegram-аккаунтам через
юзербот (Telethon): читать чаты, искать, разбирать непрочитанное, отправлять и
редактировать сообщения, работать с файлами.

Деплой не нужен: Claude сам запускает сервер как дочерний процесс на вашей машине
и общается с ним по stdio. Пока Claude закрыт, ничего не работает и не висит в сети.

## Для друзей: установщик

Другу нужен один файл — `TelegramForClaude-Setup-<версия>.exe`. Он ставится без прав
администратора и сам открывает страницу настройки в браузере:

1. **Аккаунт** — вход по QR-коду с телефона (Настройки → Устройства → Подключить
   устройство); облачный пароль, если есть, — в поле на странице.
2. **Подключить к Claude** — прописывает сервер в Claude Desktop и Claude Code.
   После этого Claude нужно полностью перезапустить.
3. **Что разрешить** — по умолчанию «только читать».
4. **Поиск по старой переписке** — архив в файле на этом же компьютере.
5. **Чаты** — какие скрыть от Claude и какие группы сохранять в архив.

Открыть настройки снова — «Telegram для Claude — настройки» в меню «Пуск». Страница
закрывается сама через полторы минуты после закрытия вкладки. Удаление — через
«Установленные приложения»; сессии и архив в `%USERPROFILE%\.telegram-mcp` при этом
остаются, их можно удалить вручную.

Windows при первом запуске может показать «Неизвестный издатель»: программа не
подписана. Нужно нажать «Подробнее» → «Выполнить в любом случае».

### Сборка установщика

Нужны uv и [Inno Setup 6](https://jrsoftware.org/isdl.php).

```powershell
Copy-Item packaging\build.env.example build.env   # вписать API ID для друзей
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Результат — `dist\TelegramForClaude-Setup-<версия>.exe`. API ID из `build.env`
зашивается в программу, чтобы друзьям не заходить на my.telegram.org. Его стоит
регистрировать на отдельный номер: если Telegram заблокирует этот ID за чьи-то
рассылки, перестанут работать все копии, но не ваш личный аккаунт. Без `build.env`
сборка тоже получится, но каждый будет вписывать свой API ID в «Дополнительно».
Достать зашитый ID из exe можно, так что секретом он не считается.

### Выпуск новой версии

Репозиторий — <https://github.com/shohrux508/telegram-for-claude>. Страница настройки у
каждого друга сама проверяет последний релиз и предлагает скачать новый установщик.

1. Поднять `__version__` в [src/telegram_mcp/__init__.py](src/telegram_mcp/__init__.py)
   и `version` в `pyproject.toml`, слить в `main`.
2. Выпустить одним из двух способов:
   - **с этого компьютера** — API ID берётся из `build.env`, а если его нет, из `.env`:
     ```powershell
     powershell -ExecutionPolicy Bypass -File packaging\release.ps1
     ```
   - **на GitHub** — запушить тег `v<версия>`. Workflow `release.yml` соберёт
     установщик и создаст релиз. API ID он берёт из секретов репозитория
     `TELEGRAM_BUILD_API_ID` и `TELEGRAM_BUILD_API_HASH`; без них соберёт программу
     без встроенного ID.

Релиз, уже выпущенный с компьютера, workflow не трогает. Тесты и линтеры гоняются
на каждый push в `main` и на каждый PR (`ci.yml`).

## Установка из исходников

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.11+. Держите проект по короткому
пути (сейчас это `C:\Telegram`): в глубоко вложенной папке
Windows упирается в лимит 260 символов и нативные модули из `.venv` не загружаются.

```powershell
uv sync --extra dev
Copy-Item .env.example .env
```

`uv sync` нужно повторять после каждого обновления зависимостей: Claude запускает
сервер с `--no-sync`, чтобы старт не зависел от сети и не переустанавливал пакеты.

В `.env` впишите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Их выдаёт Telegram на
<https://my.telegram.org> → *API development tools* (один раз, на любой свой аккаунт).

## Вход в аккаунт

```powershell
uv run telegram-mcp login
```

Команда спросит номер телефона, код из Telegram и пароль двухфакторки, если он
включён. Вводить их нужно самому в терминале: они уходят напрямую в Telegram и
нигде не сохраняются. В списке устройств Telegram сессия видна как `telegram-mcp`.

Несколько аккаунтов — по имени на каждый:

```powershell
uv run telegram-mcp login --account work
uv run telegram-mcp accounts
uv run telegram-mcp logout --account work
```

Инструменты принимают необязательный параметр `account`. Без него берётся `main`
(меняется через `TELEGRAM_MCP_DEFAULT_ACCOUNT`), а если залогинен всего один
аккаунт — он.

## Подключение к Claude

Claude Code (все проекты сразу):

```powershell
claude mcp add telegram --scope user '--' uv run --no-sync --directory C:\Telegram python -m telegram_mcp
```

Кавычки вокруг `'--'` обязательны: в PowerShell `claude` — это `claude.ps1`, и голый
`--` до него не доходит. Запуск идёт через `python -m`, а не через `telegram-mcp.exe`:
работающий сервер держит свой exe-файл занятым, и `uv sync` не смог бы его обновить.

Claude Desktop — в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "telegram": {
      "command": "uv",
      "args": ["run", "--no-sync", "--directory", "C:\\Telegram", "python", "-m", "telegram_mcp"]
    }
  }
}
```

Путь в обоих случаях — к папке этого проекта. После этого можно просить:
«что у меня непрочитанного в телеграме», «найди, где мы с Азизом обсуждали договор»,
«подготовь ответ в черновик».

## Что умеет

Список инструментов и их параметры — в докстрингах, это и есть то, что видит Claude:

- чтение — [src/telegram_mcp/tools/reading.py](src/telegram_mcp/tools/reading.py)
- изменение — [src/telegram_mcp/tools/writing.py](src/telegram_mcp/tools/writing.py)
- архив истории — [src/telegram_mcp/tools/history.py](src/telegram_mcp/tools/history.py)

Чат можно указать числовым id, `@username`, ссылкой `t.me/...`, `+телефоном`,
словом `me` (Избранное) или точным названием.

## Архив истории

Копия переписки с полнотекстовым поиском (`history_*`). Где она лежит, решает
`TELEGRAM_MCP_ARCHIVE_MODE`:

- **`local`** (по умолчанию) — файл `~/.telegram-mcp/archive.db` на этом компьютере;
  сервер не нужен.
- **`core`** — на своём сервере core (модуль `modules/tg_archive`). Включается сам,
  если заданы `TELEGRAM_MCP_CORE_URL` (корень домена core) и `TELEGRAM_MCP_CORE_TOKEN`
  (значение `MCP_TOKEN` из core).
- **`off`** — архива нет, инструментов `history_*` тоже.

Оба варианта ищут одинаково: правила поиска — копия
[search_query.py](src/telegram_mcp/search_query.py) из core, менять вместе.

**Что попадает в архив.** Личные чаты — всегда. Группы, каналы и боты — только те,
что вы включили: на странице настройки или попросите Claude («добавь группу Работа
в архив», «убери из архива и удали копию»). Скрытые чаты не попадают никогда.

**Синхронизация.** Пока Claude держит сервер запущенным, архив обновляется сам раз в
`TELEGRAM_MCP_SYNC_INTERVAL_MINUTES` (10 минут); из нескольких окон Claude синхронизирует
только одно. Архив помнит, что у него уже есть, поэтому прерванный запуск просто
продолжается со следующего раза. Вручную:

```powershell
uv run telegram-mcp sync                  # догрузить новое
uv run telegram-mcp sync --backfill 2000  # плюс 2000 более старых сообщений на чат
uv run telegram-mcp sync --watch          # работать постоянно, раз в 5 минут
```

При первом знакомстве с чатом берутся последние `TELEGRAM_MCP_SYNC_INITIAL_LIMIT`
сообщений (по умолчанию 300); глубже — через `--backfill`. Claude может запустить
синхронизацию сам (`history_sync`), но короткими заходами до 50 секунд.

Архив не видит правок и удалений в старых сообщениях: после первой выгрузки
сообщение перечитывается, только если попадёт в `--backfill`.

## Безопасность

Сервер действует от вашего имени, поэтому несколько правил зашиты в код:

- **Файл сессии = полный доступ к аккаунту.** Сессии лежат вне репозитория, в
  `~/.telegram-mcp/sessions/`. Никому не передавайте их и не коммитьте; `send_file`
  отказывается отправлять `*.session`, `.env` и всё из папки сессий.
- **Чат с кодами входа скрыт всегда.** Служебные чаты Telegram (`777000` — коды
  входа, `489000` — коды сторонних сервисов) нельзя прочитать, найти или выгрузить
  ни одним инструментом, и настройкой это не отключается. Свои чаты добавляются в
  `TELEGRAM_MCP_HIDDEN_CHATS` (id через запятую): Claude их не видит, в архив они не
  попадают. Правило одно на всё — [src/telegram_mcp/policy.py](src/telegram_mcp/policy.py).
- **Архив — это копия переписки в открытом виде**: в файле на компьютере или на вашем
  сервере под токеном core; чужие личные сообщения тоже там. Удалить копию чата —
  `history_exclude_chat` с `purge` или снять галочку на странице настройки.
- **Страница настройки слушает только `127.0.0.1`** и принимает запросы лишь с
  одноразовым токеном из адреса, который открыла сама программа: другие сайты в том
  же браузере ею управлять не могут.
- **Чужие сообщения — это данные, а не команды.** В инструкциях сервера Claude
  велено не выполнять указания из текста сообщений и подтверждать отправку. Это
  снижает риск prompt injection, но не отменяет его: не включайте автоподтверждение
  для пишущих инструментов.
- **Режим только для чтения:** `TELEGRAM_MCP_READ_ONLY=true` — пишущие инструменты
  вообще не регистрируются.
- **Название чата не превращается в юзернейм.** `Family` ищется только среди ваших
  диалогов и никогда не резолвится в чужой `@family`.
- **Чтение не меняет статус.** История и непрочитанное читаются без отметки
  «прочитано»; её ставит только `mark_read`.
- **Никаких рассылок.** Telegram банит аккаунты за спам с юзерботов; при лимите
  (`FloodWait`) сервер возвращает ошибку с временем ожидания, а не ждёт молча.

Один аккаунт одновременно используют несколько процессов: по серверу на каждое окно
Claude плюс страница настройки. Файл сессии общий, поэтому каждая запись в него сразу
фиксируется ([accounts.py](src/telegram_mcp/accounts.py), `SharedSQLiteSession`).

## Настройки

Все переменные и значения по умолчанию — в
[src/telegram_mcp/config.py](src/telegram_mcp/config.py), пример — в
[.env.example](.env.example). Источники, от сильного к слабому: переменные окружения,
`.env` (в папке проекта и в `~/.telegram-mcp/`), `~/.telegram-mcp/settings.json` —
его пишет страница настройки (`telegram-mcp settings`). Что задано в `.env`, страница
поменять не может и так и пишет. Скачанные медиа — в `~/.telegram-mcp/downloads/`.

## Разработка

```powershell
uv run pytest
uv run ruff check .
uv run mypy .
```

Тесты не ходят в Telegram: проверяют разбор ссылок на чаты, форматирование
сообщений, архив, страницу настройки и сам MCP-сервер через встроенный клиент SDK.
